## 第十八批：显式偏好跨存储恢复（2026-09-10）

- 默认 Neo4j 适配器写 L1 前，SQLite 先保存 owner 级待办；相同待办可恢复，不同修改在恢复前拒绝。数据库写入与 operation receipt 同事务，重复完成请求不再重新应用旧偏好。
- 账本使用 operation 派生的稳定 record ID；远端成功后本地仅写一半，重启恢复不会重复追加已有记录。所有记录确认后才完成待办。不同 owner 与旧 operation 无法清除新待办。
- 人工偏好删除在存在待办时拒绝，避免顺序修改覆盖未完成操作。匿名重试只使用签名身份，拒绝请求中夹带 owner；本地重试保留管理权限和运行身份检查。
- 记忆页显示待办和重试入口，保存失败后重新读取状态。默认 Neo4j 路径具备回执；未实现幂等协议的自定义适配器不获得自动重试保证。
- 回执需要 User.id 与 receipt(owner,operation) 唯一约束；现存冲突或无权限会失败关闭，不自动删除、合并用户数据。回执与账本须一起备份；尚无自动物理清理策略。
- 故障测试覆盖提交后响应丢失、SQLite 中途失败、重启、并发重试、身份隔离、旧待办完成通知和 record ID 冲突。不是跨数据库分布式事务；不能据此承诺多部署使用不同账本时全局顺序一致。
