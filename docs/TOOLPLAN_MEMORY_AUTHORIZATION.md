# ToolPlan 记忆写入授权边界

`services.authorized_memory_writer.AuthorizedMemoryWriter` 是短时、请求级的应用授权能力，供 `build_music_tool_registry(authorized_memory_writer=...)` 注入。默认 registry 继续拒绝记忆写入；不因此启用 ToolPlan 默认执行，也不替换现有人工偏好接口或 L2 consolidation。

## 应用必须先完成的事

1. 从已验证的请求身份获得 user_id，不能使用模型参数中的身份。
2. 对具体 delta 完成应用审批：显式偏好来自用户确认；推断偏好来自已有归纳校验策略。不要把模型原始 values 原样当成 approved_delta。
3. 应用选择所属用户的真实 L0 证据 ID。证据存在只能证明来源，不能证明“这段文字支持该语义结论”。本模块不使用关键词判断语义授权。
4. 提供类型对应的 commit 回调。成功必须明确返回 `{"success": true}`；持久化失败不可吞掉异常再返回成功。模型不能自行选择回调。
5. 将 writer 注入同一个请求的 registry；不要放进全局共享对象、序列化发给客户端或用作远程认证令牌。

## 强制检查

- user_id、memory_type、values、evidence_id、confidence 必须与批准内容完全一致。
- 所有证据在提交前按 owner 查询，必须为有效 L0 用户来源，不接受系统或助手生成的记录、过期、未来或已撤销证据。
- 默认有效期 60 秒，最大 300 秒；只读评测模式拒绝写入。
- 同一能力对象内并发/重复成功提交只调用回调一次，返回保存的回执。
- 回调超时、取消或返回不确定结果后，该能力不再调用写入回调；由持久化层完成对账，不允许在工具重规划时盲目重放。

## 未覆盖的边界

审批本身仍是应用责任。工具执行与批准的关联由服务器注入保证；不能把有能力构造 Python 对象的代码视作不可信调用者。

此去重范围仅为请求能力对象，不是跨进程 exactly-once。证据检查与数据库提交不是跨存储原子事务；严格撤销竞态、进程重启对账以及版本化写入恢复需要存储层支持。当前没有向默认推荐节点自动签发授权，也未公开“任意证据 ID 换取写权限”的接口。
